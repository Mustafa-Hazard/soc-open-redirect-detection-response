SOC case file — Open Redirect detection & response

0 real bypass caught, 0 false positives

A blue-team exercise that went past synthetic log samples: a live OWASP Juice Shop container was exploited for real, and the detection rule below caught the bypass that fooled the application's own security control.

Read the full runbook View the detection script GitHub repo

Exhibit A — real exploit, live target

2 alert · 2 ok · 4 total

OWASP Juice Shop, run locally via Docker. Its own redirect allowlist check (lib/insecurity.ts) uses url.includes(allowedUrl) — a substring match rather than an exact host match. Line 4 below is the result: a URL that passes Juice Shop's own check but actually redirects to evil.com.

Why this matters: the detection rule caught the bypass on line 4 even though the target application's own security control let it through. This is real, reproducible evidence that an independent detection layer adds value beyond the app's own defenses — not a simulated result.

Exhibit B — synthetic attack sample

11 alert · 1 ok · 12 total

Hand-crafted requests covering known Open Redirect bypass patterns: absolute URLs to external hosts, protocol-relative //, the @ userinfo trick, backslash-as-slash, lookalike subdomains, and non-http schemes.

Line 9 is deliberate, not a miss: accounts.ugc-creator-hub.com//.evil.co/login parses to a real, allowlisted host — .evil.co is just a path segment. A naive rule matching for // or a keyword anywhere in the string would have false-alarmed here; correct hostname parsing does not.

Exhibit C — synthetic benign sample

0 alert · 12 ok · 12 total

Normal traffic: relative-path redirects, links to the platform's own domain, and legitimate third-party destinations (OAuth continuation, payment checkout). None of it should alert.

Reproduce this yourself

No build step. Clone, install nothing beyond Python 3's standard library, and run.

# clone the repo
git clone https://github.com/Mustafa-Hazard/soc-open-redirect-detection-response.git
cd soc-open-redirect-detection-response

# run the detector against the synthetic samples
python3 scripts/detect_open_redirect.py --profile ugc samples/attack_sample.log
python3 scripts/detect_open_redirect.py --profile ugc samples/benign_sample.log

# run it against the real Juice Shop exploit log
python3 scripts/detect_open_redirect.py --profile juiceshop results/juice_shop_access.log

# optional: reproduce the live exploit yourself
docker run -d --name juice-shop -p 3000:3000 bkimminich/juice-shop
curl -v "http://localhost:3000/redirect?to=http://evil.com/?x=https://github.com/juice-shop/juice-shop"
Testing was performed exclusively against a self-hosted OWASP Juice Shop container. No third-party systems were scanned or exploited. See SOC_Runbook_Open_Redirect.md for the full triage checklist, incident-response playbook, and documented detection blind spots.
